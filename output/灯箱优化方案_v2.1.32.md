## 二、缺陷清单（必修）

### BUG-1　详情截图入口未过滤空图源

**根因**：`v2_app.js:1639` `var list = r.shots.map(imgSrc)` 没有 `.filter(Boolean)`，而卡片入口 1566 有。当 `shot.path` 为空（ZIP 导入失败、旧数据、手动改过 JSON），`imgSrc` 返回 `''`（250-254）。

**后果**
- 灯箱翻到该张时 `img.src = ''` → 浏览器把**当前文档 URL 当图片请求**（file:// 或 `http://127.0.0.1:8787/`），必然 error → 停在「加载中…」或「图片加载失败」，用户以为图片丢了。
- 详情弹窗里 `v2_app.js:888` 同样不判空 → 渲染出 `src=""` 的破图占位格。
- 若直接补 `.filter(Boolean)` 而不动 labels / `at`，会出现**标签与图片错位 + 点第 3 张打开第 2 张**（`at` 按未过滤下标算）。

**修复**：抽公共构造函数 `viewerListOf(row)`，list 与 labels **配对过滤**（同一轮 filter 中同步丢弃），返回 `{list, labels}`；三个入口统一调用；`at` 由过滤后的下标推导。

### BUG-2　`closeViewer` 用 `src = ''` 清空图片

**根因**：`v2_app.js:1082` `img.src = ''`。空串不是「无图」，浏览器按 URL 解析规则把它解析成当前文档地址并重新发起请求。

**后果**
- 每次关闭灯箱发一次无意义请求（本地服务也会走一次磁盘 IO）。
- error 回调在 `display:'none'` 之后执行，又把 `#ivLoading` 重新显示 → 灯箱留脏状态。

**修复**：改用 `removeAttribute('src')`（或 `about:blank`）；同时给 `load` / `error` 回调加 `if (!$('#imgViewer').classList.contains('show')) return;` 守卫。

### BUG-3　加载失败无恢复手段

**现状**：error 只写死文案「图片加载失败」（1792-1795），用户只能手动点下一张。

**修复**：失败态在 bar 上显示「重试 / 下一张」两个按钮；重试 = 重新赋 `src`（加 `?r=时间戳` 破缓存）。

### BUG-4　关闭入口不可见

**现状**：v2.1.18 主动删除了关闭按钮，只能点遮罩或 Esc。

**说明**：这是当年的主动决策（详情弹窗同样处理），是否回退需用户拍板（见第六节待决策项）。
**若回退**：右上角加半透明 ✕，**必须同步在 `bindViewer` 注册监听**，并保留 `ev.target.id === 'imgViewer'` 的精确判定（历史教训：删/加 HTML 控件没同步改监听，会拖垮后续所有监听绑定）。

## 三、增强项（按性价比排序）

| 级别 | 项目 | 方案 | 改动面 | 风险 |
|---|---|---|---|---|
| P0 | 相邻预加载 | 每次 `paintViewer` 后 `new Image().src = list[at±1]`（可扩 ±2） | §8 + 一个函数 | 极低 |
| P0 | 键盘与滚动 | 补 Home/End（首/末张）、`+/-`（预留给缩放）；灯箱打开时给 body 加滚动锁 | `bindViewer` | 低 |
| P0 | 卡片入口补 labels | 复用 `viewerListOf` 的 labels（「封面 / 截图 N」） | 入口① | 低（但会改变 `#ivLabel` 断言，见第五节） |
| P0 | 图片尺寸信息 | `load` 后在 label 旁显示 `naturalWidth×naturalHeight` | `paintViewer` + load 回调 | 低 |
| P1 | **缩放 / 1:1 原图** | 点击图片在「适应窗口 ↔ 原始尺寸」切换；放大态容器可拖动（`overflow:auto` 或 transform+drag）；滚轮缩放并阻止背景滚动 | CSS + §8 + 事件 | 中（居中/溢出/边界） |
| P1 | **底部缩略图条** | 底部横向滚动条，当前项高亮，点击直达；>30 张用 IntersectionObserver 懒加载 | 新 DOM + CSS + 渲染逻辑 | 中偏高 |
| P2 | 设为封面 | 灯箱里把当前截图设为该行 `cover`（含 thumb 重生成） | 数据写入 + `makeThumb` | 中 |
| P2 | 打开原图 / 下载 | `imgSrc` 即 `/data/...` URL，新标签打开或 `<a download>` | bar 按钮 | 低 |
| P2 | 视频页入口 | `part_video.js` 的 `.v-thumb` 也可点开灯箱 | part_video.js | 低 |
| P2 | 触屏与无障碍 | 左右滑动切换、双击放大；`img` 加 alt（番号+序号）、按钮 `aria-label`、打开时焦点移入灯箱并做焦点陷阱 | DOM/CSS/事件 | 低-中 |

**缩略图条的成本提示**：项目目前只给封面生成 `thumb/<code>@360.jpg`（`v2_app.js:476/506-509`），**截图没有缩略图**。缩略图条若直接用原图，99 张原图即使懒加载也偏重；若要省流量，需要服务端为 shots 也生成 @360（新增工作量，需评估）。

## 五、回归影响（提前预警）

1. **必须重建**：改 `_build/` 后执行 `node _build/build_v2.js`（根目录 `Film Library.html` 是产物，直接改会被覆盖）。
2. **必须 bump**：`_build/v2_app.js` 的 `APP_VERSION` 2.1.31 → 2.1.32。
3. **套件基线大概率要动**：
   - `_test/r12_viewer_ui_test.js` 直接测灯箱 UI；新增关闭按钮 / 重试按钮 / 尺寸文本 / 缩略图条都会改 DOM 结构与元素计数。
   - 历史上「新增一个按钮导致弹窗变高触发 `fitBoxToViewport` 缩放，连带 5 个尺寸类套件翻红」已发生过一次，本次同类风险高。
   - 卡片入口新增 labels 会改变 `#ivLabel` 的内容断言（原来为空串）。
4. **SPA 侧**：灯箱不受 Spider 影响，但若 B4 涉及服务端生成截图缩略图，则 Server 双端（server.js / server.py）也要同步改 + 版本号 bump + 跑 `_test/verify_server_norm.js` 对拍。
